# 节点通信与策略更新

## 状态与凭证的持久化保护

生产模式会在 `NODEWALL_CLUSTER_KEY_FILE` 指定的位置保存 32 字节集群密钥，默认是
`/etc/nodewall/cluster.key`。管理状态、节点凭证、登录账号和认证设置使用 AES-GCM 封装，
采用临时文件、刷盘和原子替换写入，并保留三代 `.bak.1` 至 `.bak.3` 备份。读取时如果主
文件认证失败或 JSON 损坏，会按顺序尝试备份；全部副本损坏时服务仍以可修复的空状态启动，
不会因为单个状态文件直接退出。

备用管理节点会通过已认证的 bootstrap 通道同步同一集群密钥和快照，因此主节点离线时仍可
打开本地 Web 并管理已经登记的节点。密钥与快照应纳入独立备份；取得 root 权限的攻击者可以
读取运行中的进程和本机密钥，单机文件加密不能替代 TPM、外部 KMS 或独立管理平面。

## 节点身份

生产模式下，Agent 的全部 HTTP API 都要求独立节点凭证，包括健康查询、策略修改和卸载。
凭证默认保存在 `/etc/nodewall/agent-token`，管理端登记信息保存在
`/etc/nodewall/node-credentials.json`；两者权限均为 `0600`，不会通过节点列表返回。
浏览器登录 Cookie 不会转发给 Agent。

管理端的 TCP HTTPS 和 gRPC 入口最低支持 TLS 1.2，以兼容旧版 NSS curl；QUIC/HTTP3
入口仍要求 TLS 1.3。降低 TCP 入口的协商下限不会关闭证书校验、公钥固定或节点凭证校验。

管理端分别固定信任各节点登记时提交的自签证书。新生成的自签证书标记为单节点信任锚；旧版本已经生成的非 CA 自签证书会按完整证书指纹固定校验，避免 CentOS/OpenSSL 因 `CA=true` 缺失而把本机 Agent 误报为未知。证书不匹配、节点未登记或凭证错误时，
请求会被拒绝。gRPC 备用通道也启用 TLS 和节点鉴权，QUIC 上报使用相同的独立节点凭证。
`NODEWALL_TLS_INSECURE_SKIP_VERIFY` 默认关闭；只有临时兼容旧安装时才显式打开，并应尽快配置
`NODEWALL_TLS_CA` 后恢复为 `false`。

## 登录与代理头安全

管理端登录使用 Argon2id 哈希；旧版 SHA-256 记录只在成功登录后迁移。不存在的账号、禁用账号
和错误密码都会执行等价的 dummy 哈希校验，登录验证码是短期、一次性且绑定来源的挑战。来源和
账号分别限速，账号锁定也能覆盖从多个来源发起的分布式猜测。密码、OTP、Passkey、找回密码和
账号状态变更会撤销对应的旧会话；会话 Cookie 使用 `HttpOnly`、`Secure`（HTTPS 或可信代理模式）
和 `SameSite=Strict`，认证写请求必须带 `X-NodeWall-CSRF`。Argon2id 校验有并发预算，避免攻击者
通过大量轮换来源把密码哈希本身变成内存耗尽攻击。

直接暴露管理端时不要信任转发头。只有在 TLS 由 Kubernetes Ingress 或其他明确的反向代理终止，
且 NodeWall 端口不对外开放时，才设置 `NODEWALL_TRUST_PROXY=true`。默认值为 `false`，因此客户端
伪造 `X-Forwarded-Proto: https` 不会绕过 Passkey 的 HTTPS 检查、HSTS 判断或安全 Cookie 设置。

## 注册与升级

节点管理页面生成的命令有效期为 20 分钟，注册凭证只能成功使用一次。
下载脚本、安装程序和管理端证书时，复制命令会先用管理端返回的脚本 SHA-256 校验值
校验脚本，再执行脚本。脚本内部优先使用 `curl --pinnedpubkey` 校验管理端公钥；目标机的
旧版 curl（例如 CentOS 7 自带的 7.29.0）不支持该选项时，会用 `openssl` 校验一次性下载
的管理端证书公钥，再使用该证书作为 `--cacert` 下载安装程序，不会通过删除完整性校验来
兼容旧版 curl。
注册程序会同时登记节点凭证和 Agent 自签证书，无需复制服务器私钥或关闭证书校验。

一体化安装升级后会自动创建本机凭证。旧版本的远程 Agent 没有独立登记凭证，
需要在管理端生成新命令后重新登记一次；重新登记保留原节点 ID 和实际 Agent 监听端口。
登记失败时恢复原有环境配置；注册程序拒绝将已安装的管理端误改为远程 Agent。
升级不会保留匿名控制或匿名上报入口。删除节点时同步撤销其凭证，避免节点被心跳重新加入。
管理端更新前应先记录远程节点清单，随后逐台完成登记和健康检查。

相关配置：

- `NODEWALL_AGENT_TOKEN_FILE`：本机 Agent 凭证文件。
- `NODEWALL_NODE_CREDENTIALS_FILE`：管理端登记信息文件。
- `NODEWALL_AGENT_TLS_CERT` / `NODEWALL_AGENT_TLS_KEY`：管理端与本机 Agent 分开配置证书时使用。

## 自动恢复

界面规则修改仍然立即生效。管理端自动为入、出方向建立短时恢复窗口；两方向应用、
持久化和自动确认全部成功后，恢复窗口才关闭。失败时恢复原有策略，通信中断时由 Agent
在 30 秒后恢复快照。恢复快照在应用前持久化，Agent 重启后先恢复尚未确认的旧策略。
管理端也会在更新前持久化恢复记录。管理端在确认阶段重启时，后台恢复任务会重新应用
上一个已确认的策略，再清除恢复记录；恢复期间拒绝对同一网卡继续叠加修改。
这些操作不需要额外的发布、同步或人工确认按钮。

首次试运行先挂载入方向，再写入共用数据面的出方向策略；快照保留挂载之前的状态，
原先未挂载的网卡在试运行超时后会恢复为未挂载。回退或落盘失败时保留恢复快照并自动重试，
不能通过取消安全定时器或把恢复错误当成记录不存在来跳过恢复。
自动计时回退和管理端回退请求同时到达时，共用同一次恢复结果；等待方断开不会取消正在进行的恢复。

`i40e` 网卡使用 generic XDP。实机 `2.8.20-k` 驱动在原生 XDP 卸载时出现过
`XDP Tx ring disable timeout` 和管理连接超时，因此在首次挂载前选择不会重建硬件队列的模式。
该模式仍使用 XDP/eBPF 策略和 TC 出方向处理，不切换到 iptables；接口状态返回实际挂载模式。
已经挂载的接口保持原模式，避免在策略热更新时切换驱动模式。

兼容性判断分别考虑内核接口、网卡驱动和网络拓扑，不根据 ZStack、Kubernetes 或发行版名称
给所有主机套用同一种模式：

| 场景 | 选择与恢复行为 |
| --- | --- |
| 支持 `bpf_link` 的内核和原生 XDP 网卡 | 使用原生 XDP；已有挂载保持原模式 |
| 内核没有 XDP `bpf_link`，但支持旧 XDP API | 使用 netlink 挂载，继续保留原生 XDP 能力 |
| 驱动不支持原生 XDP，或命中 i40e 连通性规避规则 | 使用 generic XDP；旧内核也可通过 netlink 挂载 |
| 内核没有 TCX | 使用旧 TC API；权限和参数错误继续报错 |
| 权限不足、接口消失、已有程序冲突 | 返回原始错误，停止模式重试，恢复已完成的步骤 |
| 管理请求超时、响应丢失或取消 | 不重新发送一次挂载来推测结果；由安全恢复流程处理 |
| 独立网卡、bond、Linux bridge / CNI | 依据真实 master 拓扑建立宿主机范围，转发流量保持原有边界 |
| XDP 能力不足 | 明确报告能力缺失；iptables 仅作为显式选择的后端 |

这些分支通过回归测试覆盖；测试中的内核 API/驱动错误模拟不代表相应硬件已经完成实机验收。

涉及 sshd 端口、当前管理来源或活动 SSH 连接来源的阻断，仍需输入控制台密码。
无法探测节点 sshd 端口时，停止应用相关策略。确认密码通过请求头/JSON 传递，
前端不再把密码放入删除请求的 URL。

## 验证

```sh
go test -race ./...
go vet ./...
GOOS=linux GOARCH=amd64 go build ./...
```

`test/integration/runtime_test.go` 启动独立的管理端和 Agent 进程，验证登录、节点注册、
独立证书信任、匿名访问拒绝和 QUIC 上报。测试数据面为 mock，不接管宿主机网卡。

Linux 上可对生成的实际 BPF 程序执行报文回归：

```sh
NODEWALL_BPF_TEST=1 go test -v ./internal/xdp -run TestXDPVLANEnforcement
```

该测试需要 BPF 权限，使用 `BPF_PROG_TEST_RUN` 验证 VLAN/QinQ、默认拒绝、SSH
放行与拒绝优先级、IPv6 和 ARP，不 attach 网卡、不修改 netfilter 规则。

## 监控历史

管理端每 5 秒通过最多 8 个并发工作线程采集节点指标，不依赖打开网页或 SSE 连接。
同一节点的并发读取共用短时缓存，离线节点不会写入伪造的零值。
样本按 UTC 小时追加到磁盘，文件权限为 `0600`；重启后可直接查询历史。
异常退出留下的末尾半条记录会在下次追加前截断，已完成的记录保持不变。

- `NODEWALL_MONITORING_HISTORY_DIR`：默认 `/var/lib/nodewall/monitoring`。
- `NODEWALL_MONITORING_HISTORY_MIB`：总磁盘上限，默认 `512` MiB，必须为正数。
- 最长保留 7 天；容量达到上限会先轮转最旧的小时文件，因此实际可用历史可能少于 7 天。
- 支持 12 小时、1 天、3 天、7 天以及自定义时间段，仍可按节点或集群查看。
- 长范围查询按时间桶取最后一个真实样本，每节点约最多 1200 点。它不是时间平均、峰值
  或完整原始采样导出；集群 CPU/内存按已有逻辑取节点平均，网络/磁盘速率相加。
- 写入失败在管理端日志和监控页面提示；查询损坏的完整记录返回错误，不伪装成空数据。
- 历史目录初始化失败时，控制台继续运行并明确提示降级为内存采样，避免附加存储故障影响管理入口。

## 扫描报告

Agent 为每次扫描保存独立 JSON 报告，开始扫描前先记录任务，完成后使用临时文件、
`fsync` 和原子替换保存结果。重启时未完成任务标记为失败，不会一直显示“扫描中”。
扫描记录页面支持分页查看历史明细，并按指定任务下载 HTML / JSON。扫描分为全量文件扫描和
隐藏 PID/已删除执行文件快速定位；运行中的扫描可以停止，停止后保留已经收集的证据。
快速扫描固定检查 `/` 下的进程视图，不开放路径选择；它同时采样高 CPU 进程、检查关键系统命令，并限定检查 systemd unit、init、cron/crontab、`rc.local`、modules-load、XDG autostart、网络/udev dispatcher、shell/profile、容器重启元数据及近期 journal 中的启动持久化证据。兼容 CentOS 7 等不支持 `journalctl --grep` 的旧系统时，扫描会读取有界的近期 journal 并在本地过滤证据。随机命名的瞬态 unit 会从 journal 中恢复名称；启动持久化必须处理真实 loader、unit、cron 或 modules-load 文件，不再创建新的 `/dev/null` 或 modprobe 启动阻断补丁。日志里的 `/dev/fd/N` 只是运行中进程的文件描述符入口，进程退出后没有可移动的持久 inode；扫描会把该引用、命令行和相关日志保存在不可恢复的证据条目中，并在相关临时载荷仍存在时单独按文件身份校验后隔离。隐藏内核模块的 `/sys/module/...` 是虚拟运行态视图，扫描会通过 `modinfo` 和受限路径搜索定位真实 `.ko` 文件；定位到的外部模块文件先进入隔离区，再尝试卸载当前模块，找不到实体文件时只报告需要可信环境恢复。使用 ZStack/libvirt 桥接的主机，iptables 兼容数据面只挂载宿主机 INPUT/OUTPUT，不挂载虚拟机 FORWARD，避免把宿主机 allowlist 误套到虚拟机 DHCP、DNS 和回包。快速扫描只会自动隔离通过完整哈希、inode、父目录和可恢复性校验的用户可控文件；系统目录和包文件需要显式隔离确认，普通高 CPU 进程、没有独立恶意特征的已删除文件和关键文件完整性发现只保留证据。证据文件以不可恢复的审计条目保存，原始日志和缺失路径不会被伪装成可恢复样本。NodeWall 隔离目录会跳过，避免把隔离样本再次当成病毒。无法可靠确定的脚本和共享解释器关联不会按名称猜测。旧内核缺少 pidfd，进程身份检查与发送信号之间仍有短暂竞态，终止进程也不能消除其持久化启动项。

- `NODEWALL_SCAN_REPORT_DIR`：默认 `/var/lib/nodewall/scan-reports`。
- 保留最近 500 次扫描；开始新扫描会轮转超限的旧报告，不会删除报告目录中的其他文件。
- 文件损坏会保留原文件并提示，不阻止 Agent 启动。
- 报告目录不可用时禁止启动新扫描并返回 `503`，但 Agent 继续恢复/维护防火墙策略和管理 API。
- `GET /nodes/{node}/security/scan/reports`：管理端历史列表。
- `GET /nodes/{node}/security/scan/reports/{scan}?format=html|json`：指定报告下载。
- 原 `GET /nodes/{node}/security/scan/report` 保留为当前任务报告入口。
- 历史报告仅供查看、下载；隔离操作仍针对当前扫描结果，隔离前重新比对文件哈希。
- 已删除但仍被进程占用的执行文件会显示 PID；具备完整身份证据的恶意样本会先保存并标记为已隔离，再尝试终止进程，样本不会自动删除。systemd 升级期间替换的可执行文件仍只作证据。
- 普通文件隔离后保存原始路径、权限、属组和支持的文件属性，隔离目录中的条目可以直接点击恢复或永久删除；
  页面操作仍会检查目标路径、普通文件类型和扫描哈希，避免误恢复或覆盖其他文件。
- 真实 `.ko` 模块隔离后不会自动复制回原始路径；模块元数据、原始摘要和文件始终留在隔离区。只有明确确认的“从隔离区加载”才会使用 `insmod` 载入，随后可以再次明确卸载，形成可逆的取证/回滚链路。
- 恢复、永久删除和人工处理进程都通过页面操作确认；快速扫描的自动处置只对通过身份、哈希和隔离核验的用户可控文件及恶意进程执行，journal/完整性证据会先写入隔离区并保留为不可恢复审计条目。

内置扫描器现在以固定大小缓冲区检查符合大小限制的整个文件，不再只检查前 4 MiB。
单独出现 `curl`、`wget`、`systemctl enable` 或 `LD_PRELOAD` 不再直接报高危；下载/
解码并管道执行等组合证据才会触发对应规则。超过 32 MiB 的文件、读取错误分别计数，
不会计入已扫描文件或被显示为完整覆盖；网页上传未完整检查时拒绝传输。
快速扫描还会检查临时目录中低 CPU 的运行程序，并关联仍由 Shell 打开的普通脚本与描述符脚本；
单独的临时路径只作为排查线索。自动处置仍要求进程身份、实际文件、哈希和多项高风险行为
同时成立，并先保存证据。父进程和 cgroup 是溯源线索，不会仅凭这些信息处置父进程。扫描不会
读取管道，也不能在进程退出后恢复已经消失的描述符内容；内核模块证据的归档不表示模块已卸载。

全量扫描会覆盖单独挂载的常见本地文件系统，以及 tmpfs 类型的 `/tmp`、`/var/tmp` 和
`/dev/shm`。默认跳过远程、其他虚拟和重复挂载及容器层存储；这些路径可作为明确指定的扫描
根目录单独检查。报告记录具体的覆盖缺口和原因，最多列出 100 项，
并统计超出的条目。符号链接不会在普通文件遍历中跟随；快速扫描会检查 systemd 启动链接的
实际普通文件并记录关联路径。默认文件大小上限为 32 MiB、文件数量上限为 200000、
风险项上限为 200；启动项检查和文件系统权限也有边界。报告显示覆盖范围完成不等于主机安全。

NodeWall 离线包提供私有 ClamAV 引擎及病毒库。任意已注册节点具备资源后，其余节点会在
启动时及每 2 分钟通过固定证书的 HTTPS 通道检查、同步缺失或较旧的引擎和数据库，管理节点
也可从其他 Agent 拉取。接收方校验摘要、原始 CVD 签名及完整数据库加载，失败保留原有版本；
引擎升级后自动重启私有 `clamd`。入群命令完成后同步在后台继续，可通过 Agent 日志和扫描
报告中的引擎状态确认是否可用。

也可接入已由管理员部署和维护的本机 ClamAV `clamd`：在 Agent 的运行环境中设置
`NODEWALL_CLAMD_SOCKET=/绝对路径/clamd.sock`，然后重启 Agent。systemd 安装可将该项加入
`/etc/nodewall/nodewall.env`。外部 `clamd` 的安装与数据库更新由管理员维护；应检查
ClamAV 数据库及更新任务，并检查报告中的引擎版本和状态。全量文件扫描使用本地 Unix socket
的 `INSTREAM` 协议检查同一个已打开文件，并重新核对哈希；符合路径安全条件的命中样本可进入
隔离区。快速扫描和 SSH 上传检查当前不调用该引擎。未配置时明确报告仅使用内置规则；连接失败、
超时或 `StreamMaxLength` 限制会记录特征库覆盖缺口。需要按 ClamAV 配置调整流大小限制。
若被命中的普通文件正由进程直接执行，处置前还需核验进程、文件 inode 和完整哈希，先保存
样本，再停止对应进程并隔离原文件；系统及平台受保护程序仍只保留证据。

启发式规则和病毒特征库都存在漏报和误报，不能保证新病毒、无文件攻击、被隐藏的内核行为或已
消失的临时载荷一定被发现。出现内核完整性异常时，应从可信环境保全证据并调查、恢复主机。

普通 SFTP 文件级上传检查、Bash 顶层命令审计与连接筛选已加入，边界和验收项见
[SSH 审计与上传检查](ssh-audit-upload.zh-CN.md)。它们不等同于全 Shell、内核级或防篡改审计。
本轮已补齐原生数据面的 TC eBPF 出方向强制过滤；监控页面现在接入磁盘设备明细和
GPU 采集。GPU 采集会按主机已安装的工具自动选择 NVIDIA、ROCm、Ascend、Cambricon、
摩尔线程、燧原、壁仞、海光等适配器，并回退到 Linux DRM/sysfs；每种设备支持的指标
由驱动动态返回，页面会按实际可用字段展示。
本轮未部署测试服务器，页面实机交互、多节点长期运行和升级恢复仍需验收。
