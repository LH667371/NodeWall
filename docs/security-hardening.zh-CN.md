# 节点通信与策略更新

## 节点身份

生产模式下，Agent 的全部 HTTP API 都要求独立节点凭证，包括健康查询、策略修改和卸载。
凭证默认保存在 `/etc/nodewall/agent-token`，管理端登记信息保存在
`/etc/nodewall/node-credentials.json`；两者权限均为 `0600`，不会通过节点列表返回。
浏览器登录 Cookie 不会转发给 Agent。

管理端的 TCP HTTPS 和 gRPC 入口最低支持 TLS 1.2，以兼容旧版 NSS curl；QUIC/HTTP3
入口仍要求 TLS 1.3。降低 TCP 入口的协商下限不会关闭证书校验、公钥固定或节点凭证校验。

管理端分别固定信任各节点登记时提交的自签证书。证书不匹配、节点未登记或凭证错误时，
请求会被拒绝。gRPC 备用通道也启用 TLS 和节点鉴权，QUIC 上报使用相同的独立节点凭证。

## 注册与升级

节点管理页面生成的命令有效期为 20 分钟，注册凭证只能成功使用一次。
下载脚本、安装程序和管理端证书时，复制命令会先用管理端返回的脚本 SHA-256 校验值
校验脚本，再执行脚本。脚本内部优先使用 `curl --pinnedpubkey` 校验管理端公钥；目标机的
旧版 curl（例如 CentOS 7 自带的 7.29.0）不支持该选项时，会用 `openssl` 校验一次性下载
的管理端证书公钥，再使用该证书作为 `--cacert` 下载安装程序，不会通过删除完整性校验来
兼容旧版 curl。
注册程序会同时登记节点凭证和 Agent 自签证书，无需复制服务器私钥或关闭证书校验。

一体化安装升级后会自动创建本机凭证。旧版本的远程 Agent 没有独立登记凭证，
需要在管理端生成新命令后重新登记一次；重新登记保留原节点 ID 和实际 Agent 监听端口。
登记失败时恢复原有环境配置；注册程序拒绝将已安装的管理端误改为远程 Agent。
升级不会保留匿名控制或匿名上报入口。删除节点时同步撤销其凭证，避免节点被心跳重新加入。
管理端更新前应先记录远程节点清单，随后逐台完成登记和健康检查。

相关配置：

- `NODEWALL_AGENT_TOKEN_FILE`：本机 Agent 凭证文件。
- `NODEWALL_NODE_CREDENTIALS_FILE`：管理端登记信息文件。
- `NODEWALL_AGENT_TLS_CERT` / `NODEWALL_AGENT_TLS_KEY`：管理端与本机 Agent 分开配置证书时使用。

## 自动恢复

界面规则修改仍然立即生效。管理端自动为入、出方向建立短时恢复窗口；两方向应用、
持久化和自动确认全部成功后，恢复窗口才关闭。失败时恢复原有策略，通信中断时由 Agent
在 30 秒后恢复快照。恢复快照在应用前持久化，Agent 重启后先恢复尚未确认的旧策略。
管理端也会在更新前持久化恢复记录。管理端在确认阶段重启时，后台恢复任务会重新应用
上一个已确认的策略，再清除恢复记录；恢复期间拒绝对同一网卡继续叠加修改。
这些操作不需要额外的发布、同步或人工确认按钮。

涉及 sshd 端口、当前管理来源或活动 SSH 连接来源的阻断，仍需输入控制台密码。
无法探测节点 sshd 端口时，停止应用相关策略。确认密码通过请求头/JSON 传递，
前端不再把密码放入删除请求的 URL。

## 验证

```sh
go test -race ./...
go vet ./...
GOOS=linux GOARCH=amd64 go build ./...
```

`test/integration/runtime_test.go` 启动独立的管理端和 Agent 进程，验证登录、节点注册、
独立证书信任、匿名访问拒绝和 QUIC 上报。测试数据面为 mock，不接管宿主机网卡。

Linux 上可对生成的实际 BPF 程序执行报文回归：

```sh
NODEWALL_BPF_TEST=1 go test -v ./internal/xdp -run TestXDPVLANEnforcement
```

该测试需要 BPF 权限，使用 `BPF_PROG_TEST_RUN` 验证 VLAN/QinQ、默认拒绝、SSH
放行与拒绝优先级、IPv6 和 ARP，不 attach 网卡、不修改 netfilter 规则。

## 监控历史

管理端每 5 秒通过最多 8 个并发工作线程采集节点指标，不依赖打开网页或 SSE 连接。
同一节点的并发读取共用短时缓存，离线节点不会写入伪造的零值。
样本按 UTC 小时追加到磁盘，文件权限为 `0600`；重启后可直接查询历史。
异常退出留下的末尾半条记录会在下次追加前截断，已完成的记录保持不变。

- `NODEWALL_MONITORING_HISTORY_DIR`：默认 `/var/lib/nodewall/monitoring`。
- `NODEWALL_MONITORING_HISTORY_MIB`：总磁盘上限，默认 `512` MiB，必须为正数。
- 最长保留 7 天；容量达到上限会先轮转最旧的小时文件，因此实际可用历史可能少于 7 天。
- 支持 12 小时、1 天、3 天、7 天以及自定义时间段，仍可按节点或集群查看。
- 长范围查询按时间桶取最后一个真实样本，每节点约最多 1200 点。它不是时间平均、峰值
  或完整原始采样导出；集群 CPU/内存按已有逻辑取节点平均，网络/磁盘速率相加。
- 写入失败在管理端日志和监控页面提示；查询损坏的完整记录返回错误，不伪装成空数据。
- 历史目录初始化失败时，控制台继续运行并明确提示降级为内存采样，避免附加存储故障影响管理入口。

## 扫描报告

Agent 为每次扫描保存独立 JSON 报告，开始扫描前先记录任务，完成后使用临时文件、
`fsync` 和原子替换保存结果。重启时未完成任务标记为失败，不会一直显示“扫描中”。
扫描记录页面支持分页查看历史明细，并按指定任务下载 HTML / JSON。

- `NODEWALL_SCAN_REPORT_DIR`：默认 `/var/lib/nodewall/scan-reports`。
- 保留最近 500 次扫描；开始新扫描会轮转超限的旧报告，不会删除报告目录中的其他文件。
- 文件损坏会保留原文件并提示，不阻止 Agent 启动。
- 报告目录不可用时禁止启动新扫描并返回 `503`，但 Agent 继续恢复/维护防火墙策略和管理 API。
- `GET /nodes/{node}/security/scan/reports`：管理端历史列表。
- `GET /nodes/{node}/security/scan/reports/{scan}?format=html|json`：指定报告下载。
- 原 `GET /nodes/{node}/security/scan/report` 保留为当前任务报告入口。
- 历史报告仅供查看、下载；隔离操作仍针对当前扫描结果，隔离前重新比对文件哈希。

内置扫描器现在以固定大小缓冲区检查符合大小限制的整个文件，不再只检查前 4 MiB。
单独出现 `curl`、`wget`、`systemctl enable` 或 `LD_PRELOAD` 不再直接报高危；下载/
解码并管道执行等组合证据才会触发对应规则。超过 32 MiB 的文件、读取错误分别计数，
不会计入已扫描文件或被显示为完整覆盖；网页上传未完整检查时拒绝传输。
这些仍是启发式风险规则，不是完整恶意软件特征库，也不保证未命中的文件安全。

普通 SFTP 文件级上传检查、Bash 顶层命令审计与连接筛选已加入，边界和验收项见
[SSH 审计与上传检查](ssh-audit-upload.zh-CN.md)。它们不等同于全 Shell、内核级或防篡改审计。
本轮补齐不代表整个产品已经完成。原生数据面的出方向强制过滤、监控告警及 GPU 采集仍需完善。
本轮未部署测试服务器，页面实机交互、多节点长期运行和升级恢复仍需验收。
