# SSH 审计与上传检查

## 当前实现

沿用 SSH 防护页面已有开关，不额外增加启用步骤。默认不启用，不改动未配置 SSH 控制的机器。
启用时需要管理端密码确认；`sshd -t` 校验配置、`sshd -T` 确认实际 ForceCommand 后才 reload，
不 restart sshd，不修改监听端口、认证方式或防火墙放行规则。
应用前校验统一辅助二进制的 Go 构建入口与功能探针；拒绝缺失、旧版或独立 Agent 二进制，
避免配置生效后 SSH 登录调用到不兼容程序。自编译请使用 `go build ./cmd/nodewall`，不要只编译 main.go。
NodeWall 的全局配置块写入主 sshd_config，不依赖系统是否包含 sshd_config.d。
禁用时移除自己的块并恢复原 SFTP Subsystem；配置检查、reload 或状态保存失败时恢复旧配置。
启用时先安装辅助文件再更新配置引用；停用时等 sshd reload 成功后才删除辅助文件。
若恢复 reload 无法确认成功，保留仍可能被引用的辅助程序，避免制造新的 SSH 登录失败窗口。
这些操作不是跨文件原子事务，强杀/断电后的配置一致性仍需纳入实机恢复验收。
Agent 更新重启只重新校验、安装之前已启用的控制，不自动打开新功能。失败保留旧配置并提示。

## SFTP 上传

启用上传检查后，SFTP 请求进入 Go 辅助进程，仍以 sshd 认证后的账号权限访问文件系统。
辅助进程使用项目已有的 SFTP 库，无需安装新的 SFTP 服务或杀毒包。

- 每个文件先写入目标目录内私有的临时目录，未检查的数据不会提前覆盖目标文件。
- 完整检查上传文件，符合内置规则的文件才提交。检查未完成、发现风险、写入错误、
  超过 32 MiB 或连接中断时拒绝提交并保留原文件。
- 支持普通上传、覆盖、追加、下载、目录浏览、创建/删除目录、重命名及常用属性操作。
- 单个通道同时最多 8 个待检查文件；随机偏移和稀疏写入也执行大小限制。
- 检查和提交使用已打开的文件及目录描述符，避免目录或临时路径被替换后提交另一份内容。
- 检查模式下拒绝最终目标为符号链接、设备或多硬链接的文件；不支持创建链接。
- 已有文件保留属主、基本权限；Linux 保留 SELinux 标签、POSIX ACL 和 user.* 扩展属性。
  不继承原可执行文件的 setuid/setgid 或 capabilities。新文件默认 `0600`，客户端可显式调整普通权限。
- 正常结束和中断会清理本次暂存内容。进程被 SIGKILL/断电可能留下 `.nodewall-upload-*`
  私有目录；为避免误删仍在使用的目录，不自动递归删除这些异常遗留。
- 并发改写目标会尽量检测并拒绝覆盖；这不是跨进程文件锁，也不阻止有本机写权限的进程自行修改文件。

启用检查时，传统 SCP 通道拒绝传输，提示改用 SFTP，避免旧式“先落地、传完再检查”造成漏检窗口。
现代 scp 客户端可能使用 SFTP，因此 SFTP/SCP 控制按实际协议区分，而非按客户端程序名称区分。
标准日志参数 `-f` 与 `-l` 可以保留；其他自定义 SFTP 参数（如只读 `-R`、指定目录）不做静默忽略；配置检查发现不支持的参数时拒绝应用，
防止用通用辅助进程意外取消已有约束。现有自定义 ForceCommand、chroot 和特殊 Match 配置仍需单独适配。
应用前会保守检查 Include 中的这些限制；含不支持的限制或歧义路径时拒绝应用，不静默替换。

内置规则属于启发式风险检查，可能误报、漏报；“未发现风险”不代表病毒库意义的安全证明。
SFTP 检查也不是全局防泄漏：拥有 SSH Shell 的账号仍可通过其他命令、端口或应用写入文件。

## 命令与连接记录

- 连接建立、结束、来源 IP/端口、系统账号、SSH 通道编号、非交互命令退出码可记录和筛选。
- Bash 使用 DEBUG 钩子记录顶层执行命令，包括退出命令；不录制终端输入、按键或程序内的密码输入。
- 保留用户启动文件；已有 DEBUG 钩子不覆盖，改为记录“审计不可用”。其他 Shell 保留原行为并明确提示不支持。
- Bash 命令在执行前记录，不把它伪装成已成功完成；交互式命令不提供逐条准确退出码，通道关闭记录真实 Shell 退出码。
- 原命令文本可能直接包含密码、令牌等敏感参数；日志不适合对不可信账号开放。
- 审计为尽力而为：账号可关闭钩子、切换 Shell 或绕过辅助进程。它不是内核级 exec 审计，也不是防篡改审计。
- Bash 管道写入是非阻塞且有界的，拥塞时可能丢弃记录；日志写入设有超时和并发限制，避免日志磁盘故障阻塞 SSH。

## 日志与普通账号

默认日志为 `/var/log/nodewall/ssh-activity.log`，通过 `NODEWALL_SSH_ACTIVITY_LOG` 配置。
JSON 行使用 `0600`，同时兼容读取旧版键值格式。最多保留当前文件和 3 个轮转文件，每个约 10 MiB。
接口覆盖这些保留文件；旧版超大文件只查询末尾 10 MiB，下一次写入时轮转。

Linux Agent 提供本地 Unix socket 接收普通账号的记录，通过 `SO_PEERCRED` 获取实际 UID，
客户端不能自报另一个账号写入日志。socket 不监听网络端口，客户端验证接收服务的 UID。
最多 16 个并发连接，每 UID 每秒最多 100 条记录；解析长度、命令长度和磁盘占用均有限制。
这不验证客户端上报的来源 IP/通道字段，也不阻止同一账号伪造操作记录，不用于自动封禁或权限判断。

`GET /nodes/{node}/ssh-protection/activity` 支持 `session`、`event`、`source`、`user` 和 `limit`（最多 500）。
页面支持类型、来源筛选，点击通道编号可查看本次通道的命令和传输记录。
